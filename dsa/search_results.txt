DSA COMPARISON - Linear Search vs Dictionary Lookup (+ Binary Search)
==============================================================================
Dataset      : 1691 real transactions from modified_sms_v2.xml
Method       : every id in each subset looked up once, repeated 200 times;
               times are the AVERAGE per single lookup (us = microseconds)

 Records | Linear search |   Dict lookup | Binary search | Dict speed-up
------------------------------------------------------------------------------
      20 |      0.273 us |      0.054 us |      0.314 us |          5.1x
     100 |      1.073 us |      0.055 us |      0.421 us |         19.5x
     500 |      4.951 us |      0.053 us |      0.606 us |         93.7x
    1000 |     10.787 us |      0.054 us |      0.736 us |        199.4x
    1691 |     17.442 us |      0.055 us |      0.890 us |        314.5x

Worst case - searching for an id that does NOT exist:
     20 records: linear    0.449 us (checks all 20)  vs  dict    0.078 us
    100 records: linear    1.970 us (checks all 100)  vs  dict    0.074 us
    500 records: linear    9.788 us (checks all 500)  vs  dict    0.081 us
   1000 records: linear   18.998 us (checks all 1000)  vs  dict    0.080 us
   1691 records: linear   35.830 us (checks all 1691)  vs  dict    0.094 us

--- Reflection ---
* With the required 20 records, dictionary lookup was 5.1x faster.
* With all 1691 records, it was 314.5x faster.
* Linear search is O(n): it checks records one by one, so its time grows
  as the dataset grows (on average it checks half the records).
* Dictionary lookup is O(1) on average: Python hashes the id and jumps
  straight to the record, so its time stays about the same at every size.
* Trade-off: the dictionary uses extra memory and takes O(n) to build once,
  and it only helps with exact-id lookups, not ranges (e.g. between two dates).

Other structures that could improve searching:
* Binary search on a list sorted by id - O(log n); measured above. Slower than
  a dictionary but keeps data ordered, so it also supports range queries.
* Balanced binary search tree (AVL / red-black) - O(log n) search, insert and
  delete while staying sorted.
* B-tree index (used by databases like MySQL/PostgreSQL) - O(log n), efficient
  for sorted and range queries on large data stored on disk.

All three methods returned the same transaction for every lookup (verified).
